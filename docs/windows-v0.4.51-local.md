# Windows v0.4.51 · 对话与连续执行修复

仅本地 Windows 交付。不推送 GitHub、不发布 Release、不安装或重启现有 HPClaw，不修改真实集群任务、脚本或分析结果。

## 原因与改动

1. 聊天区原先只渲染末尾 500 条消息，工具返回值还有显示层截断。现在已保存的用户/助手正文完整显示在同一对话中；增加中英文“一键展开执行记录”。工具与思考记录仍可收起以减少干扰，展开后不再截断显示。内部计划检查点等协议元数据仍不显示。模型上下文预算独立限制，不删除聊天历史；无法恢复旧版本保存前已截断且未留原始记录的文本。
2. 同一对话并发完成的不同作业，原互斥逻辑会直接丢掉后到事件；DSH 后台续跑新提交的作业没有继续登记；原生续跑缺少原对话与计划；流程的 waiting_jobs 还会被 step.running 覆盖。现改为逐项排队、保留同一 RUN 的持久唤醒记录、跟踪后续作业、恢复原对话和计划、锁内合并调度器状态。DSH 在原对话忙碌时等待其结束再投递，避免把旧轮回答当作续跑结果。明确显示“自动验收中”，不把正常后台验收误当成要求用户点击继续。
3. 原来每条开始/续跑协议消息都会生成一个流程框。现在按 workflowId/runId/runDir 标识在同一对话内去重，保留一个实时卡片和每次恢复的用户指令；不同 RUN 仍分别显示。

## 执行边界

- 仅连续执行已经授权的任务；关键输入缺失、QC 不合格、必须审批、用户停止仍会明确暂停。
- 监控器只有查到明确终态才生成调度器完成事件；空结果、查询错误或仍在 RUN/PEND 不算 DONE，保留作业 ID 继续核查。
- 调度器 DONE 只表示作业结束，不等于产物有效或 QC 合格。后台 Agent 必须检查真实日志和输出后更新步骤，并继续后续步骤。
- 复用原提交幂等门禁，不因为超时或通知重发就重复提交。拒绝后台批准高风险操作。
- 自动继续需要软件后台运行、集群连接可用和有效 AI 配置。并不保证第三方模型、网络或软件环境永不出错；异常必须说明未核验状态。

## 验证与交付

- 自动化覆盖：超 500 条消息、完整工具/思考内容、同一 RUN 与不同 RUN、并发完成通知、DSH 原轮忙碌、后续作业登记、原生计划恢复、三步输出验收与连续推进、明确审批/失败暂停。
- 使用隔离的 616 条模拟历史页面做实际浏览器检查，未连接集群或调用真实模型；该 QA 页面不进入安装包。
- 构建使用 --publish never；安装载荷检查 CRC。安装包无代码签名，Windows 可能显示未知发布者。请先保存当前任务并自行关闭 HPClaw，再运行安装程序。
- 最终测试计数、安装包 SHA-256 和打包后隔离冒烟结果保存到本地交付目录。外部文献元数据网络测试未执行时单独标记，不计为通过。

本版本不改变 v0.4.50 的流程图依赖、待弃置管理和 ENCODE/DAP 工作流科学实现。
