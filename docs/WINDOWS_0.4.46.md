# HPClaw v0.4.46 — Windows 质控风险提醒

本次只构建 Windows x64 安装包，保留经典界面和 v0.4.45 的报告预览、英文流程修复；不部署 Mac/Linux 网页版，不改用户集群、历史对话或正在运行的作业。

## 提醒与继续规则

- 已记录的 QC `fail` 显示醒目的红色提醒：“质控未通过：质量不佳，不建议继续下游分析”。步骤详情折叠时也可见，并展示实际指标、已声明的通过标准、原始摘要。
- QC `warn` 显示黄色警告，建议核查指标并谨慎解释结果；不会把警告误判为失败。QC `pass` 或尚未记录 QC 时不虚构失败。
- 正式 RUN 存在未确认的 QC 失败时暂停自动推进，普通继续、调度器 DONE、全部步骤执行成功不能绕过该暂停；原生 Agent 同一轮中的新提交也受校验。已在运行的作业不自动取消。
- 用户可以先查看日志；如确需继续，必须点击“仍要继续（不推荐）”并再次“确认风险并继续”。后端使用当前 revision 校验，在运行记录中保存确认时间与 revision，但 QC 仍为 `fail`，报告保留风险提醒。
- 运行状态更新后旧确认界面关闭；新的 QC 判定清除旧确认，失败时需要重新审阅。明确重跑会清除目标及后续步骤旧 QC 判定，但保留标准与脚本。
- 新建 RUN 把流程中已声明的 QC 标准绑定到对应步骤。这些步骤完成前必须记录有效 `pass/warn/fail`，不能把退出码 0 当作质控通过。原生和 DSH 提示均要求依据实际指标与已有标准，不擅自调整阈值或归因为测序深度。

## 语言与判断边界

新提示、标准标题和风险确认按钮支持专业中英文；指标数值、样本名、路径和原始日志不被翻译改写。浅色与深色主题均使用可读的语义文字颜色。

本次不增加通用数值阈值，也不从任意日志文字猜测 QC 失败：各实验类型须使用自身流程已声明的标准，由分析步骤记录结构化 QC。旧 RUN 不会静默补写判定；缺少 QC 标准的自定义脚本不因此获得自动数值判定能力。任意脚本内部一次性提交的整条级联，无法在尚未回传 QC 时被该关卡事后截断；应拆成可验收的正式步骤。

## 验证与安装

测试覆盖失败/警告/通过、终态误判、确认记录、版本冲突、新 QC 使确认失效、API 会话、实际 Agent 提交阻断、调度器对账以及折叠卡片和中英文界面。界面验证使用隔离演示数据，不代表用户的实际样本结论。

2026-10-09 最终验证：202 个测试文件通过，1572 项测试通过、2 项可选测试跳过；TypeScript 检查、生产构建、安装包 CRC、打包后的后端/DSH/语言偏好/文献学习检查，以及更新清单 SHA-512 校验均通过。QC 增量包含 28 项回归测试，界面实测发现的英文漏项与浅色主题可读性问题已修正。

安装前正常关闭 HPClaw，再运行 `HPClaw-Setup-0.4.46-x64.exe`，不需要删除应用数据。本次不自动安装或重启。初次交付为本地构建，后续按用户要求发布到 GitHub；公开发布信息见 [版本发布说明](WINDOWS_0.4.46_RELEASE.md)。安装包未签名时 Windows 可能显示“未知发布者”。
