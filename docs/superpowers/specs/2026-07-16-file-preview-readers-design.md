# HPClaw 远程文件受管编辑与预览设计

## 目标

HPClaw 的文件操作分成两个明确入口：

- 双击远程文件或选择“打开并编辑”时，完整下载文件，调用 Windows 默认软件打开，并把用户的修改自动上传覆盖到原集群路径。
- 右键选择“预览”时，在 HPClaw 内只读查看常见格式；大于或等于 100 MB 的行式文本和生物信息文件只显示前 20 行。

本地文件双击后直接用系统默认软件打开，不产生集群上传任务。

## 当前问题

- `FilePane` 和 `FilePreview` 存在两套预览实现，实际入口仍由 `FilePane` 自行展示。
- 远程接口返回 base64、本地 Electron IPC 返回二进制对象，但旧对话框直接把 `content` 放进 `<pre>`，会显示编码内容或错误对象。
- 双击文件与右键“预览”行为混在同一个文本预览函数中，没有系统默认软件打开能力。
- 没有远程文件下载、外部编辑、关闭检测、自动回传和失败恢复组成的完整编辑会话。
- 远程预览统一限制为 1 MiB，无法按文件类别选择读取策略。

## 方案选择

采用“现有传输队列 + Electron 受管编辑会话 + 应用内只读预览”的组合方案。

- 现有传输队列继续负责远程文件的完整下载和上传，复用其进度、暂停、重试、校验及临时文件原子替换能力。
- Electron 主进程负责创建安全缓存路径、调用系统默认软件、监听本地副本变化并检测打开程序结束。
- React 工作区负责编排编辑会话状态、展示同步状态，以及触发右键只读预览。

没有采用以下方案：

- 新建一套直接 SFTP 下载/上传接口：会重复传输队列已有的重试、校验和原子覆盖逻辑。
- 仅调用 `shell.openPath` 后不跟踪会话：无法可靠回传编辑结果，也无法在失败时保留和恢复本地副本。

## 交互规则

### 双击与打开编辑

- 双击远程普通文件等同于右键“打开并编辑”。
- 双击本地普通文件调用系统默认软件，不创建编辑会话。
- 目录双击仍然进入目录。
- 右键菜单同时提供“打开并编辑”和“预览”，两者含义不得混用。
- 远程编辑需要完整下载，不受 100 MB 预览阈值影响。

### 右键只读预览

应用内预览支持：

- 图片：PNG、JPEG、GIF、BMP、WebP、SVG、ICO。
- 文档：PDF、DOCX。
- 表格：XLSX、XLS、CSV、TSV。
- 富文本：Markdown。
- 文本：常见代码、配置、日志和 HPC/生物信息文本格式，包括 FA/FASTA/FQ/FASTQ、SAM、VCF、GFF/GTF、BED 等。

PPT/PPTX、压缩包、视频和未知二进制格式本次不做应用内渲染，但仍可通过“打开并编辑”交给系统默认软件。

## 受管编辑会话

### 会话模型

每次打开远程文件都会创建一个编辑会话：

```ts
interface RemoteEditSession {
  id: string;
  sshSessionId: string;
  profileId: string;
  remotePath: string;
  localPath: string;
  state: 'downloading' | 'opening' | 'editing' | 'uploading' | 'synced' | 'failed';
  dirty: boolean;
  lastLocalFingerprint?: string;
  lastUploadedFingerprint?: string;
  error?: string;
}
```

缓存目录位于 Electron `userData/remote-edit-sessions/<session-id>/`，文件名保留原扩展名，使 Windows 能选择正确的默认软件。同一路径重复打开时聚焦已有会话，不并发创建多个可互相覆盖的副本。

### 数据流

1. 工作区请求 Electron 创建编辑会话并取得安全缓存路径。
2. 工作区把现有下载任务加入传输队列，目标为该缓存路径。
3. 下载完成后，Electron 使用 Windows 默认文件关联打开缓存文件。
4. Electron 监听文件大小、修改时间和内容指纹变化；保存完成且文件稳定后把会话标记为待同步。
5. 默认软件进程结束或文件锁释放后，工作区执行最终同步检查。
6. 若内容有变化，现有上传队列把缓存文件上传到原远程路径，冲突策略固定为直接覆盖。
7. 上传成功后记录已同步指纹；只有会话已同步并结束时才允许清理缓存。

### 关闭检测与保存兜底

Windows 文件关联可能复用已经运行的 Word、Excel 或其他进程，因此单独等待新进程退出并不可靠。实现采用双重机制：

- 优先使用可等待的系统默认程序启动方式，在启动进程结束时触发最终同步。
- 同时监听缓存文件。检测到保存后等待短暂稳定窗口，自动发起一次同步；关闭时再比较指纹并执行最终同步。

因此，即使默认程序无法报告准确关闭时间，用户已保存的修改仍会自动上传。重复保存使用指纹去重，不上传未变化内容，也不并发上传同一会话。

### 覆盖与失败恢复

- 自动上传始终直接覆盖原远程文件，不检查或提示远程并发修改。
- 上传仍使用远程临时文件加原子重命名，避免失败时留下半个文件。
- 上传失败时编辑会话进入 `failed`，保留本地缓存文件并提供“重试上传”和“打开本地副本”。
- SSH 断线时会话保留；重新连接到同一配置后允许重试。
- HPClaw 关闭时，如存在未同步或上传中的编辑会话，关闭确认框必须明确提示；用户强制关闭也不能删除缓存。

## 只读预览架构

### 读取策略

集中式文件类型检测模块输出预览类型、MIME 和读取模式：

- `binary`：图片、PDF、DOCX、XLSX，读取完整文件但受分类硬上限约束。
- `text`：Markdown、代码、日志、CSV及常规文本，在安全字节上限内读取并解码。
- `head`：大于或等于 100 MB 的行式文本或生信文件，流式读取至 20 行后立即停止。
- `unsupported`：不可识别或超出二进制预览上限，只显示元数据、原因和“打开并编辑”。

`head` 模式必须按块读取并在得到 20 行后停止，不能先读取完整大文件。无换行文件另设最大扫描字节数。

### 阅读器

- 图片使用浏览器原生解码并提供缩放。
- PDF 使用 `pdfjs-dist` 分页阅读。
- DOCX 使用 `docx-preview` 只读渲染。
- XLSX/XLS/CSV/TSV 使用 `xlsx`，支持工作表切换和滚动表格。
- Markdown 复用 `react-markdown`，不启用原始 HTML。
- 代码、日志和生信文本使用等宽字体、行号、横向滚动和复制。

旧的 `FilePane.previewContent` 对话框移除。右键“预览”只把 `FileEntry` 和本地/远程来源交给工作区级 `FilePreview`，确保只有一套预览实现。

## 安全与性能

- Electron 生成缓存根目录和会话目录；渲染进程不能指定任意缓存路径。
- 远程路径继续使用现有绝对路径校验和 SSH 会话校验。
- 本地编辑缓存不暴露到浏览器 URL，也不以内联 HTML 注入文档内容。
- SVG 只在 `<img>` 隔离上下文中展示；Markdown 禁止原始 HTML。
- 预览读取有服务端硬上限；大文本 `head` 有行数和扫描字节双重上限。
- 编辑会话保存指纹和状态，避免文件监视器重复事件造成重复上传。

## 错误处理与状态展示

- 下载期间显示“正在准备本地副本”和传输进度；下载成功后才启动默认软件。
- 系统没有关联程序时，显示可理解的错误，不创建上传任务。
- 编辑会话状态在文件工作区内可见：编辑中、正在同步、已同步、同步失败。
- 预览解析错误只影响内容区，不关闭文件工作区。
- 切换文件或关闭预览时取消未完成的只读读取，并释放 Blob URL。

## 测试与验收

- 单元测试覆盖远程/本地双击路由、右键菜单两个入口和目录导航不变。
- Electron 测试覆盖安全缓存路径、同一路径会话复用、默认软件启动失败、文件变化去抖和关闭最终检查。
- 编辑会话测试覆盖下载后打开、保存后上传、直接覆盖、指纹去重、上传失败保留缓存和重新连接后重试。
- 类型检测测试覆盖 100 MB 边界、生信格式、大小写扩展名和未知二进制。
- 本地与远程读取测试证明 `head` 模式读到 20 行即停止，并遵守无换行扫描上限。
- React 测试覆盖图片、Markdown、文本 `head -20` 提示、PDF/DOCX/XLSX 阅读器选择、解析失败和迟到响应。
- 运行 TypeScript 检查、完整 Vitest、Vite 构建和 Electron 相关测试；实际验证至少一种系统默认文档编辑、一次自动覆盖上传、一次上传失败恢复及各类只读预览。

## 完成标准

远程文件双击后能由 Windows 默认软件打开，用户保存并关闭后修改自动覆盖回原集群路径；同步失败不会丢失本地修改。右键“预览”以统一的应用内阅读器展示支持格式，100 MB 及以上的行式文本只读取并显示前 20 行，不再出现 base64 原文。
