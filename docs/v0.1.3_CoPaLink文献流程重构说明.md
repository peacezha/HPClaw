# HPClaw v0.1.3：文献流程导入重构

## 这次解决的问题

旧版文献学习采用一次性“论文全文 → 流程 JSON”，只验证步骤是否有标题和命令。它容易把摘要当全文、把对照实验混入主流程、用常识补造参数，并且不会保留论文与代码不一致之处。

v0.1.3 将这条链路改为“方法章节选择 → 论文/代码双来源提取 → 工具实体对照 → 确定性质量审计 → 人工确认 → 可编辑 Agent 流程”。

## CoPaLink 带来的设计纠偏

CoPaLink 的主要任务不是直接重建整条工作流，而是：

1. 从论文中识别生物信息学工具；
2. 从可执行工作流代码中识别工具；
3. 使用工具名称、知识库或语义表示对齐两种来源中的工具实体，并显式保留未匹配项。

HPClaw v0.1.3 采用了这套“分来源识别 + 显式对齐 + 不确定性保留”的产品原则，但没有声称复现 CoPaLink 的训练语料和专用 NER/实体消歧模型。参考：[CoPaLink 论文](https://arxiv.org/abs/2603.08195)、[公开代码](https://gitlab.liris.cnrs.fr/sharefair/copalink)。

## 新的导入合同

每个文献步骤现在可保存：

- `kind`：决策、计算、QC 或报告；
- `sourceType`：论文或代码仓库；
- `sourcePath` / `sourceSection`：来源文件与章节；
- `evidence`：证据短句转述；
- `confidence`：高、中、低可信；
- `inputs` / `outputs`：步骤输入和预期产物；
- `requiresReview`：运行前是否必须人工确认；
- 步骤级可调参数、默认值、类型和必填规则。

没有完整 CLI 时，导入器必须生成 `# REVIEW_REQUIRED:` 草稿，而不是猜一条看似可运行的命令。

## 确定性质量审计

服务端不采信 AI 自报分数，而是按保存后的结构计算五项分数：

- 证据覆盖；
- 可执行性和步骤输入输出；
- 参数声明完整度；
- 软件/参考数据资源清单；
- QC 步骤和门禁。

审计会显示总分、阻断项、警告、待确认问题、排除的对照/替代分支，以及论文工具与代码工具的 `已匹配 / 仅论文 / 仅代码 / 未验证` 状态。用户必须在编辑器确认审计信息后才能保存文献草稿。

## Agent 运行行为

运行文献流程时，Agent 必须：

1. 读取每一步的来源、证据、可信度、输入和预期输出；
2. 对低可信或 `requiresReview=true` 的步骤先向用户确认；
3. 不把 Bioconda 包存在误当成论文工具与代码命令已经对应；
4. 每一步完成后核对真实产物是否覆盖预期输出；
5. 保持原有的计划、LSF Job ID、步骤状态、QC 和最终报告监控。

## PDF 与正文处理改进

- PDF 读取上限由 25 页提高到 50 页，并尽量保留换行；
- 正文不再机械截取开头，而是优先识别 `Methods`、`Workflow`、`Implementation`、`Data analysis` 等章节；
- 仍保留标题/摘要上下文和代码仓库链接；
- DOI 只能得到摘要或出版商落地页时，审计会明确阻断，不再把结果标成完整流程。

- TypeScript 类型检查通过；
